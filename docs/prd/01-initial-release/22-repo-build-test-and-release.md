# 22. Repo, build, test and release

Source: [Repo layout, build toolchain and testing strategy](https://github.com/qodesmith/unimatrix-zero/issues/41), [ADR 0016](../../adr/0016-releases-built-and-signed-on-the-maintainers-machine.md).

- **Layout.** A Bun-workspaces monorepo: `shell/`, `app/main/`, `app/preload/`, `app/renderer/`, `app/provider-host/` (`claude/` and `chatgpt/` entries), `shared/contract/`, plus the Report Worker beside the contract. Isolated installs; `tsc -b` project references enforce boundaries; Cerebro-style deep modules (`src/modules/<name>/main.ts`, lint-enforced; `.tsx` only under `ui/`; tests beside their unit). Drizzle stays in main.
- **Build.** Vite 8 everywhere, fully bundled: main and hosts as ESM, preload as one self-contained CJS file, shell as CJS. electron-builder 26.x and electron-updater in `shell/` with an exhaustive fuse config. `bun run dev` runs the renderer through `app-dev://`, watch-builds the rest, restarts Electron or a single host on change, with per-worktree ports and data folders and a `--fake` driver.
- **Tests.** Vitest in two projects: node (contract, main, hosts, shell; database tests under Electron's own Node) and renderer in browser mode. A runtime-match check pins Electron's Node and SQLite versions. Fakes only at boundaries; real in-memory SQLite with migrations. Provider layers: a fake `ProviderDriver`; NDJSON transcripts recorded at the process boundary and replayed by fake `claude`/`codex` binaries (the weekly bump fails if they no longer match); live tests local and opt-in only. Playwright E2E on a test build (onboarding; send, stream, Stop, Fork; a Workspace write; update and Restart; bundle rollback after a failed migration). Packaged smoke of the real fused artifacts, which also checks real shells reject the test key.
- **CI** checks and never ships: format, lint (oxlint type-aware, zero warnings), typecheck (TypeScript 7), knip; unit, E2E and smoke on Mac arm64, Mac x64, Windows x64 and Linux x64; the weekly vendor bump; Electron advisories. No git hooks.
- **Releases** are built and signed on the maintainer's Mac by `bun run release`: preflight with a reviewed diff since the manifest's source commit, local build and tag, live tests against the exact `.asar`, draft upload, CI smoke by manual dispatch, sign the manifest with the key read from Bitwarden into memory, push the tag, publish, push the manifest to Pages. Shells embed the newest published signed bundle.
