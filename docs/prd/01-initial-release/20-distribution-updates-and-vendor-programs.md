# 20. Distribution, updates and vendor programs

Source: [Distribution and update strategy](https://github.com/qodesmith/unimatrix-zero/issues/13), [Unsigned distribution research](https://github.com/qodesmith/unimatrix-zero/issues/5), [Ship the vendor programs or use the user's installed copies](https://github.com/qodesmith/unimatrix-zero/issues/20), [App name, sidebar label and visual identity](https://github.com/qodesmith/unimatrix-zero/issues/33), ADRs [0006](../../adr/0006-unsigned-distribution.md), [0007](../../adr/0007-thin-shell-signed-app-bundles.md), [0008](../../adr/0008-app-managed-vendor-programs.md), [0012](../../adr/0012-stable-identity-separate-from-display-name.md), [0016](../../adr/0016-releases-built-and-signed-on-the-maintainers-machine.md).

- **Unsigned.** Ad-hoc signed on Mac, unsigned on Windows and Linux, published to GitHub Releases with a GitHub Pages download page. The page detects the OS, puts that OS's download first (Mac: universal by default, with Apple Silicon and Intel alternatives remembered in `localStorage`), shows first-launch steps with screenshots (Mac Open Anyway; Windows SmartScreen More info → Run anyway; Linux chmod), a "Windows won't open it?" section for Smart App Control (accepted as a loss), and a "Using a terminal?" section. The README links to it.
- **Files shipped.** Mac: `.dmg` for arm64, x64 and universal, plus `install.sh` (curl, no quarantine, no Open Anyway; SHA-256 from the manifest; arch from `sysctl`). Windows: x64 per-user one-click NSIS (`install.ps1` only if PowerShell downloads prove to avoid SmartScreen). Linux: x64 AppImage, installed by `install.sh` into `~/.local/bin` with a menu entry, also offered directly. No `.deb`/`.rpm`, no portable `.exe`, no MSI.
- **Thin shell and signed app bundles.** The installed app is a small Electron shell whose loader runs the app code from a versioned, Ed25519-signed bundle in `userData`, listed in a signed manifest on GitHub Pages (monotonic `sequence`, `expires` about 30 days out, each bundle's source commit, `minShell`, hashes, vendor program versions, `reports`, `fixed`). The loader verifies the signature on every launch; falls back to the last known good bundle, then the copy built into the shell; a bundle is "good" once the database opened, migrations ran and the window rendered, and a bundle that never gets there rolls back with the pre-migration backup restored. First launch fetches the latest compatible bundle before showing the UI (about 5 s, then the built-in copy). On Mac the shell's unchanging `cdhash` keeps privacy grants across app-code updates; a first launch outside `/Applications` calls `moveToApplicationsFolder()`.
- **Updates.** The app checks the manifest on launch and every few hours (a Setting). "Update available" pill with Download and a "What's new" link; nothing downloads until the click; then "Restart to update". Code is never swapped mid-session. Restarting into a newer bundle shows what's new once. Shells ship only for high/critical Electron or Chromium fixes, to stay on a supported Electron major, or when a bundle needs a newer shell: Mac shells replace their own `.app`; Windows and Linux use electron-updater's `generic` provider at the manifest's `shell-N` tag with the download hashed against the manifest. Versioning is one product version (`v1.8.2`) plus a shell generation (`shell-3`, 3.0.0 for electron-updater); About shows "1.8.2 (shell 3)". A failed verification shows "This update couldn't be verified. Reinstall from [download page]."
- **Vendor programs.** Exact, unmodified `claude` and `codex` builds are downloaded on Connect from the vendors into `userData`, hash-checked against the manifest, never re-signed, never taken from the user's PATH, each with its own `CLAUDE_CONFIG_DIR` / `CODEX_HOME` (`settingSources: []`, auto memory off, self-updaters off). Codex is a folder, not a file. On Linux, bubblewrap and socat are downloaded beside them as app-managed helpers and hashed in the manifest ([§10](./10-the-sandbox.md), [ADR 0008](../../adr/0008-app-managed-vendor-programs.md)). Users who already sign in to `claude` or `codex` elsewhere sign in once more. Versions move with app bundles: a weekly CI job bumps the SDK and Codex, regenerates the types, runs smoke tests (including the MCP OAuth smoke) and opens a PR; new programs download with their bundle before "Restart to update"; the previous version is deleted once the new bundle is good. No Setting to point the app at another copy, only a developer-only environment variable.
- **Identity.** "Unimatrix Zero" is the shipped name; `appId` `com.qodesmith.unimatrixzero`, `userData` folder `unimatrix-zero` (set by the shell's loader), Archive format id `unimatrix-zero-archive` and Linux binary `unimatrix-zero` never change.
- **Secrets.** The app never stores or handles Provider credentials and uses no keychain or `safeStorage`. User-supplied values such as MCP tokens are stored as plainly as the vendor tools store them, and never archived.

## Verify while building

- Whether the standalone `codex-app-server` build covers sign-in, the Sandbox and Workspace tools, or the full `codex` folder is needed ([#20](https://github.com/qodesmith/unimatrix-zero/issues/20), [#41](https://github.com/qodesmith/unimatrix-zero/issues/41)).
- Whether Codex's model list exposes the minimum Codex version for gated models; else catch the error and show "Needs an app update" on the Reply ([#20](https://github.com/qodesmith/unimatrix-zero/issues/20)).
- Quarantine, translocation and privacy-grant behavior on macOS 27 (experiments ran on 26.6) ([#13](https://github.com/qodesmith/unimatrix-zero/issues/13)).
- Whether PowerShell downloads avoid SmartScreen, deciding `install.ps1`; Smart App Control re-enable wording against Microsoft's current docs ([#13](https://github.com/qodesmith/unimatrix-zero/issues/13)).
- The loader never requires an unverified bundle, including last-known-good and the built-in copy ([#39](https://github.com/qodesmith/unimatrix-zero/issues/39)).
- Where each vendor stores MCP OAuth tokens under our config folders, and that an app update after an MCP sign-in causes no Keychain prompt ([ADR 0006](../../adr/0006-unsigned-distribution.md)).
