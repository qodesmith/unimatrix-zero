# 17. Settings and Themes

Source: [Settings and user preferences](https://github.com/qodesmith/unimatrix-zero/issues/22), [ADR 0009](../../adr/0009-themes-are-versioned-token-only-json.md), [ADR 0023](../../adr/0023-three-kinds-of-setting-and-a-trees-own-permission-mode.md), plus sections added by later tickets.

**Principle.** An option earns a Setting only when reasonable users want either value and the default is known. Everything is stored in SQLite (`settings`, the System prompt library, `themes`). The theme mode is read before the window opens to avoid a flash.

**Three kinds of Setting** ([ADR 0023](../../adr/0023-three-kinds-of-setting-and-a-trees-own-permission-mode.md)):

- **Look and behavior:** global. It applies at once and never reaches the AI. The theme mode and the Theme, Font size, canvas orientation, "Limit height of long messages", the Context size meter, the send key, the re-read note, Esc stops a Reply, and update checks.
- **Defaults for new Trees:** copied into a Tree when it is created, and never changing an existing one. The default System prompt, the Tools defaults, and each library entry's "On in new Trees".
- **Live AI Settings:** global, reaching every Tree from the next AI call.
  - The Permission mode: a Tree may use its own instead ([§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)).
  - The Compaction Settings: they reach every Thread from its next Reply, and no Tree has its own in v1.
  - The Summary prompts ([§13](./13-summaries.md)): no Tree has its own.

The libraries (System prompts, MCP servers, Skills, Plugins) are content, as Themes are, not Settings ([§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)). A Tree's own values are shown and changed in its **Tree panel**, never here.

**Reach on the page.** Every group of controls holds one reach only. A group of look-and-behavior Settings has no note, since applying at once and never reaching the AI is what a user expects. Every other group has one note under its legend:

| Group                                                                              | Note                                                                                                                             |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| The Permission mode                                                                | "Every Tree that doesn't use its own mode, from the next Reply."                                                                 |
| The Tools defaults                                                                 | "A Tree you already made keeps its own switches. Change them in its Tree panel, from the ⋯ menu beside its name in the sidebar." |
| The default System prompt                                                          | "New Trees start with a copy. Each Tree changes its own in its Tree panel."                                                      |
| The System prompt library                                                          | "Each Tree keeps its own copy. Editing here changes no existing Tree."                                                           |
| The MCP server, Skill and Plugin libraries, and the vendors' default Skill folders | "Editing an entry reaches every Tree that uses it. 'On in new Trees' affects only Trees created later."                          |
| Each Provider's Compaction Settings                                                | "Every Thread, from its next Reply."                                                                                             |
| The Summary prompts                                                                | "Every Summary made from now on."                                                                                                |

A saved flip in the Tools defaults shows a line under the group: "Saved for new Trees. Trees you already made kept their own." The group's legend reads "Defaults for new Trees", since a user who flips one there may expect the open Tree to change ([#294](https://github.com/qodesmith/unimatrix-zero/issues/294)).

**The narrowing prompt.** Narrowing the global Permission mode can leave Trees with a wider mode of their own; [§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md) says when the prompt appears and what it does.

**Font size** runs from 12 to 24 pixels in steps of 2. Beside its control on this page, ⌘+ and ⌘− change it a step at a time, and ⌘0 sets it back to 16. It grows text and the widths that cap a line of it, not the spacing, and it is not Zoom, which scales the canvas alone; the window itself never zooms.

**Deliberately not Settings:** a default Model for new Trees (last-used), a simple/advanced mode, interface language. Neither are the Connections cards, which are account state, nor Layout, such as Storage's "Show breakdown" ([ADR 0021](../../adr/0021-layout-is-kept-apart-from-settings.md)).

**Themes.** A Theme is versioned JSON of token values only (shadcn colors and radius, canvas colors, a Shiki theme name, a font family) with a `light` set, a `dark` set, or both; never CSS. A single-set Theme is used in every mode with the mode control disabled and a note. Each set needs a background, foreground and primary color, and the app works out every other color from them; a missing radius, font or Shiki theme comes from the built-in Theme, and export writes only what the Theme's author wrote ([ADR 0009](../../adr/0009-themes-are-versioned-token-only-json.md), amended); unknown keys are ignored; invalid files are rejected with a plain-language error. Import a `.json` (pick or drag), export any Theme, and a "Browse themes" link that opens the GitHub Pages gallery in the browser (the app never fetches it). Built-in Themes live in code; all UI styles use tokens only. The default Theme is "Hearth" ([§23](./23-visual-identity.md)).
