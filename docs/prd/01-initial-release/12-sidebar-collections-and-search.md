# 12. Sidebar, Collections and search

Source: [Tree sidebar](https://github.com/qodesmith/unimatrix-zero/issues/34) (prototype, variant B, amended), [Export, Archive and Summary entry points](https://github.com/qodesmith/unimatrix-zero/issues/30), [Full-text search](https://github.com/qodesmith/unimatrix-zero/issues/43), [⌘K search](https://github.com/qodesmith/unimatrix-zero/issues/44) (prototype, variant A), [Usage and limit display](https://github.com/qodesmith/unimatrix-zero/issues/36), [App name, sidebar label and visual identity](https://github.com/qodesmith/unimatrix-zero/issues/33).

- **Layout.** Three resizable sections, VS Code Explorer style: **Trees**, **Files** ([§9](./09-workspaces.md)) and **Usage** ([§16](./16-usage-and-limits.md)), with draggable dividers (double-click resets) and collapse to header. Minimum heights 120 / 180 / 90 px. Sidebar width 290 px (default and minimum) to 640 px. Width, splits and collapsed state survive switching Trees and launches. The gear opens Settings. The UI calls them "Trees"; the empty state says "Start a new Tree" with a one-line explanation.
- **Rows.** Title (the root Prompt's first line in italic until the automatic title arrives), relative time, a dot while a Reply streams, a red dot for an unseen failure. Renaming by double-click, F2 or ⋯ → Rename is final. The **⋯ menu**: Rename, Storage…, Summarize this Tree…, Export Tree…, Archive…, Move to Collection…, Delete…. It floats anchored to its row.
- **Collections.** One level, user-made, 📁 icon, never called folders ("New Collection", "Move to Collection…", "Rename Collection", "Delete Collection"; deleting one returns its Trees to the top level). Trees go in by drag or the menu. No pins. Sort menu: Last active (default), Date created, Name. ⌘/Shift-click selects several for Move to… or Delete….
- **Deleting** one or several Trees asks with the Turn count, Workspace versions deleted, a note that a linked folder stays put, "Deleting frees up to X", and "Archive first…".
- **Search** is a ⌘K palette (or "Search all Trees") over titles, Prompt text, the visible text of Replies and attachment file names, using SQLite FTS5 (`unicode61 remove_diacritics 2`, prefix match per word, every word must match in the same Turn or the title; queries under 3 characters and Chinese/Japanese fall back to a plain scan). Not indexed: thinking, tool calls and output, Subagent work, Workspace files, System prompts. Prompts index when sent, Replies once when finished; triggers keep deletes and restores in sync and are recreated after every migration.
- **The palette.** Empty: "Recent", up to 8 Trees (last opened from search first, then by activity), persisted between launches. Results: one row per Tree (title with matches marked, Collection, Provider dots, last active, one snippet from the best match labelled "You" or "Reply" with a Model pill), "▸ N more in this Tree" expanding inline. Ranking: title match, then how many Turns match with diminishing weight, then recency; a sort menu offers Last active and Date created. Filter chips: Titles only, Collection, Provider, Date. Keyboard: ↑↓, → expand, ← back, Enter open, Esc close. Opening a result opens the Tree with the chat slideout on that Turn, with only that Turn's matches marked on the canvas and in the slideout; Esc clears the marks.

## Verify while building

- FTS5 ranking weights, the title boost and the recency nudge, tuned on real data ([#44](https://github.com/qodesmith/unimatrix-zero/issues/44)).
