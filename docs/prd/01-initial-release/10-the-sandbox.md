# 10. The Sandbox

Source: [Vendor sandboxing for commands the AI runs](https://github.com/qodesmith/unimatrix-zero/issues/49), [Live tests](https://github.com/qodesmith/unimatrix-zero/issues/53), [Sandbox edges](https://github.com/qodesmith/unimatrix-zero/issues/56), [Check what Cowork and ChatGPT desktop let a command reach](https://github.com/qodesmith/unimatrix-zero/issues/55), [ADR 0018](../../adr/0018-commands-run-inside-the-vendor-sandbox.md).

- **The card decides whether a command runs; the Sandbox decides what it can reach.** Every command in a run-commands Workspace runs inside the vendor's Sandbox, set to what that vendor's desktop app does. Write files Workspaces have no shell and nothing to sandbox.
- **Codex:** `workspace-write`, network off, approvals `on-request`. **Claude:** the SDK `sandbox` option with writes allowed only in the working copy, temp and the package caches; a credentials deny list (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.kube`, `~/.gnupg`, keychains, the app's own Provider folders) mirrored as Read-tool deny rules; network default-deny with an empty allowlist. Reads are the whole disk minus credentials on both (the one place we differ from Cowork, which runs in a VM). Other Branches' working copies and the hidden store are on the deny list. Subagents inherit the parent's Sandbox.
- **Inside the Sandbox, no card.** Cards remain for everything the Sandbox does not cover: the fence itself, the Read deny rules, file tools outside the working copy, web fetch, MCP servers.
- **At the fence, one card family.** A blocked path or connection makes the Model ask to run outside (Claude's `dangerouslyDisableSandbox` retry, Codex's escalation); the card says the command would run outside the Sandbox, and its "Always allow" covers only that form. Claude's blocked connection also arrives as a `SandboxNetworkAccess` prompt naming the host; its "Always allow" is the per-host rule. Every Bash allow rule the app writes is paired with the ask rule `Bash(dangerouslyDisableSandbox:true)`, or the retry would be approved silently. No built-in allowlist in v1. The standard per-user package caches (bun, npm, pnpm, yarn, pip, cargo, the OS cache folder) are writable on both so installs stay inside.
- **Linux** gets bubblewrap and socat as app-managed helpers beside the vendor programs, first on Claude's `PATH`; Codex brings its own. The app probes before each session (`bwrap --unshare-user --ro-bind / / true`) and starts the Sandbox off when the probe fails.
- **Where the Sandbox is unavailable** (native Windows on both vendors; Linux where bubblewrap cannot run), commands still run and the user is told once when turning on run commands, with the Tools panel saying so while it is on. Claude runs with the Sandbox off; Codex with `danger-full-access` and `approval_policy: untrusted`, so losing the floor does not also remove the cards. **Windows position: from docs, verification pending** ([#58](https://github.com/qodesmith/unimatrix-zero/issues/58)).
- **YOLO** removes approvals and the Sandbox together ([§8](./08-system-prompts-the-tools-panel-approvals-and-yolo.md)).
