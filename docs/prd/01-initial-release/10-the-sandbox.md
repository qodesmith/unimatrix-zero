# 10. The Sandbox

Source: [Vendor sandboxing for commands the AI runs](https://github.com/qodesmith/unimatrix-zero/issues/49), [Live tests](https://github.com/qodesmith/unimatrix-zero/issues/53), [Sandbox edges](https://github.com/qodesmith/unimatrix-zero/issues/56), [Check what Cowork and ChatGPT desktop let a command reach](https://github.com/qodesmith/unimatrix-zero/issues/55), [the same on Windows](https://github.com/qodesmith/unimatrix-zero/issues/58), [ADR 0018](../../adr/0018-commands-run-inside-the-vendor-sandbox.md), amended by [ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md) and [The non-developer's path](https://github.com/qodesmith/unimatrix-zero/issues/285).

- **The card, or under Auto the Reviewer, decides whether a command runs; the Sandbox decides what it can reach.** Under the Permission modes Auto, Auto-accept edits and Supervised ([§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)), every command runs inside the vendor's Sandbox, set to what that vendor's desktop app does. **Full access**, the default, removes approvals and the Sandbox together (Claude `bypassPermissions` with the Sandbox off; Codex `danger-full-access` with `approval_policy: never`); it is the only mode without the Sandbox.
- **Codex:** `workspace-write`, network off. Approvals `on-request` under Auto-accept edits, which asks only at the Sandbox boundary; the same with `approvalsReviewer: 'auto_review'` under Auto, so the Reviewer answers instead of the user; `untrusted` under Supervised, which runs Codex's known-safe read-only commands and asks for the rest. **Claude:** the SDK `sandbox` option with writes allowed only in the working copy, temp and the package caches; a credentials deny list (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.kube`, `~/.gnupg`, keychains, the app's own Provider folders) mirrored as Read-tool deny rules; network default-deny with an empty allowlist. Reads are the whole disk minus credentials on both (the one place we differ from Cowork, which runs in a VM). Other Branches' working copies and the hidden store are on the deny list. Subagents inherit the parent's Sandbox.
- **Inside the Sandbox, the mode decides whether a command asks.** Under Auto the Reviewer decides whether a command may leave the Sandbox, and the Sandbox limits what an approved one reaches. Under Auto-accept edits a command that stays inside the Sandbox runs without asking, as ADR 0018 decided and as the vendors' desktop apps do. Under Supervised every command the vendor does not recognize as read-only asks, and the Sandbox decides what an approved one can reach. Reads never ask: a read the deny list covers is refused, not carded. Cards remain too for what the Sandbox does not cover: the Sandbox boundary itself, file tools outside the working copy, web fetch, MCP servers.
- **At the Sandbox boundary, one card family.** A blocked path or connection makes the Model ask to run outside (Claude's `dangerouslyDisableSandbox` retry, Codex's escalation); the card says the command would run outside the Sandbox, and its "Always allow" covers only that form. Claude's blocked connection also arrives as a `SandboxNetworkAccess` prompt naming the host; its "Always allow" is the per-host rule. Both cards lead, in plain words, with what the command could then read, change or reach, since "outside the Sandbox" or a host name alone tells a non-developer nothing. Every Bash allow rule the app writes is paired with the ask rule `Bash(dangerouslyDisableSandbox:true)`, or the retry would be approved silently. Under Auto the Reviewer answers these requests in the user's place ([§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)). No built-in allowlist in v1. The standard per-user package caches (bun, npm, pnpm, yarn, pip, cargo, the OS cache folder) are writable on both so installs stay inside.
- **Linux** gets bubblewrap and socat as app-managed helpers beside the vendor programs, first on Claude's `PATH`; Codex brings its own. The app probes before each session (`bwrap --unshare-user --ro-bind / / true`) and starts the Sandbox off when the probe fails.
- **Windows:** Codex runs inside MXC, its newer Windows Sandbox that needs no administrator setup, which ChatGPT desktop prefers for consumer accounts on Windows 11 24H2 ≥ 26100.9278 / 25H2 ≥ 26200.9278. The app sets `features.prefer_mxc = true` in its own Codex config folder with the same `workspace-write` and network off; the legacy `elevated` (UAC prompt, two local users, firewall filters, profile-wide read ACLs) and `unelevated` modes are never used. The probe is the Windows build. Claude has no Sandbox on native Windows (watched live in [#58](https://github.com/qodesmith/unimatrix-zero/issues/58)).
- **Where the Sandbox is unavailable** (Claude on native Windows; Codex below MXC's minimum build; Linux where bubblewrap cannot run), commands still run and the user is told once, when a Permission mode that needs the Sandbox is chosen, with Settings saying so while it is on. The notice is in plain words, with no AppArmor, user namespaces, bubblewrap or build numbers: on this computer the AI's commands aren't kept to the Tree's files and off the internet, and the mode's cards, or under Auto its Reviewer, still come first. Where a Windows update would bring the Sandbox (Codex below MXC's minimum build), it says to update Windows. Claude runs with the Sandbox off; Codex with `danger-full-access` and `approval_policy: untrusted`, so losing the floor does not also remove the cards.
