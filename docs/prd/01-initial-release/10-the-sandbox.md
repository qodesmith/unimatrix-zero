# 10. The Sandbox

Source: [Vendor sandboxing for commands the AI runs](https://github.com/qodesmith/unimatrix-zero/issues/49), [Live tests](https://github.com/qodesmith/unimatrix-zero/issues/53), [Sandbox edges](https://github.com/qodesmith/unimatrix-zero/issues/56), [Check what Cowork and ChatGPT desktop let a command reach](https://github.com/qodesmith/unimatrix-zero/issues/55), [the same on Windows](https://github.com/qodesmith/unimatrix-zero/issues/58), [ADR 0018](../../adr/0018-commands-run-inside-the-vendor-sandbox.md), amended by [ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md).

- **The card decides whether a command runs; the Sandbox decides what it can reach.** Under the Permission modes Auto-accept edits and Supervised ([§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)), every command runs inside the vendor's Sandbox, set to what that vendor's desktop app does. **Full access**, the default, removes approvals and the Sandbox together (Claude `bypassPermissions` with the Sandbox off; Codex `danger-full-access` with `approval_policy: never`). Whether Auto keeps the Sandbox is open (below).
- **Codex:** `workspace-write`, network off, with the approval policy that gives the mode's cards (ADR 0018's `on-request` asks only at the Sandbox boundary, so the policy that brings a card for every command is open in [§8](./08-system-prompts-the-tools-panel-approvals-and-permission-modes.md)). **Claude:** the SDK `sandbox` option with writes allowed only in the working copy, temp and the package caches; a credentials deny list (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.kube`, `~/.gnupg`, keychains, the app's own Provider folders) mirrored as Read-tool deny rules; network default-deny with an empty allowlist. Reads are the whole disk minus credentials on both (the one place we differ from Cowork, which runs in a VM). Other Branches' working copies and the hidden store are on the deny list. Subagents inherit the parent's Sandbox.
- **Every command gets a card.** ADR 0018 let a command that stays inside the Sandbox run without asking; under Auto-accept edits and Supervised every command now asks, and the Sandbox decides only what an approved one can reach. Reads never ask: a read the deny list covers is refused, not carded. Cards remain too for what the Sandbox does not cover: the Sandbox boundary itself, file tools outside the working copy, web fetch, MCP servers.
- **At the Sandbox boundary, one card family.** A blocked path or connection makes the Model ask to run outside (Claude's `dangerouslyDisableSandbox` retry, Codex's escalation); the card says the command would run outside the Sandbox, and its "Always allow" covers only that form. Claude's blocked connection also arrives as a `SandboxNetworkAccess` prompt naming the host; its "Always allow" is the per-host rule. Every Bash allow rule the app writes is paired with the ask rule `Bash(dangerouslyDisableSandbox:true)`, or the retry would be approved silently. No built-in allowlist in v1. The standard per-user package caches (bun, npm, pnpm, yarn, pip, cargo, the OS cache folder) are writable on both so installs stay inside.
- **Linux** gets bubblewrap and socat as app-managed helpers beside the vendor programs, first on Claude's `PATH`; Codex brings its own. The app probes before each session (`bwrap --unshare-user --ro-bind / / true`) and starts the Sandbox off when the probe fails.
- **Windows:** Codex runs inside MXC, its newer Windows Sandbox that needs no administrator setup, which ChatGPT desktop prefers for consumer accounts on Windows 11 24H2 ≥ 26100.9278 / 25H2 ≥ 26200.9278. The app sets `features.prefer_mxc = true` in its own Codex config folder with the same `workspace-write` and network off; the legacy `elevated` (UAC prompt, two local users, firewall filters, profile-wide read ACLs) and `unelevated` modes are never used. The probe is the Windows build. Claude has no Sandbox on native Windows (watched live in [#58](https://github.com/qodesmith/unimatrix-zero/issues/58)).
- **Where the Sandbox is unavailable** (Claude on native Windows; Codex below MXC's minimum build; Linux where bubblewrap cannot run), commands still run and the user is told once, when a Permission mode that needs the Sandbox is chosen, with Settings saying so while it is on. Claude runs with the Sandbox off; Codex with `danger-full-access` and `approval_policy: untrusted`, so losing the floor does not also remove the cards.

## Verify while building

- Whether commands stay inside the Sandbox under Auto, on both vendors ([ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md), open).
- Windows: whether `app-server` honors `prefer_mxc` from our config folder on the pinned Codex, how MXC availability surfaces beyond the `MXC availability` log line, and what the `InitializeDefaultDrives` noise on every PowerShell command means for our output ([#58](https://github.com/qodesmith/unimatrix-zero/issues/58)).
- `bypassPermissions` plus the ask rule; Codex `writable_roots` with `~/.bun`; the Ubuntu 24.04 AppArmor case on real hardware ([#53](https://github.com/qodesmith/unimatrix-zero/issues/53)).
