# 21. Architecture

Source: [Tree storage and source of truth](https://github.com/qodesmith/unimatrix-zero/issues/11), [SQLite + Drizzle research](https://github.com/qodesmith/unimatrix-zero/issues/8), [AI and chat-UI library stack](https://github.com/qodesmith/unimatrix-zero/issues/12), [Provider drivers, process model and IPC event list](https://github.com/qodesmith/unimatrix-zero/issues/38), [Electron security posture](https://github.com/qodesmith/unimatrix-zero/issues/39), ADRs [0001](../../adr/0001-app-owns-the-tree.md) to [0005](../../adr/0005-no-ai-library.md), [0013](../../adr/0013-utility-process-per-provider-main-is-the-hub.md), [0014](../../adr/0014-electron-security-posture.md), [0015](../../adr/0015-types-derive-from-schemas-ipc-contract.md).

```text
renderer (React, React Flow, TanStack Query + Store)
  │  window.uz = { send, subscribe, registerDroppedFile }   one typed channel, Zod-validated
main (SQLite via Drizzle, hub, saves then forwards, SNAPSHOT on connect)
  ├── Provider host: Claude   (utility process; Claude Agent SDK → claude)
  └── Provider host: ChatGPT  (utility process; app-server JSON-RPC client → codex)
```

- **Storage.** The app's SQLite database (`userData/data/unimatrix.sqlite`, `node:sqlite` through Drizzle 1.0 rc, better-sqlite3 13 as fallback, WAL, main process) owns every Tree; history is rendered only from it. Provider sessions are disposable copies: continue resumes, branch uses the native fork at that Reply (Claude `resume` + `resumeSessionAt` + `forkSession`; Codex `thread/fork` with `lastTurnId`), anything else goes through the one "rebuild session from Thread" path (exact restore from the app's own opaque copy of the session, silently; else Codex `inject_items`; else text replay, the last two with the re-read note). Deleting rewinds the session (Codex `thread/revert`; Claude `resumeSessionAt` on the next continue). Schema: separate `prompts` and `replies` tables (Forks only at Replies), Reply content as ordered provider-neutral JSON parts plus Provider, Model, status, System prompt reference, session coordinates and Context size; `system_prompts` append-only by hash; attachments on disk by hash; `settings`, `themes`; Workspace columns and `working_copies`; FTS5 tables with triggers. UUIDv7 ids everywhere. Migrations run on start behind a backup (keep 3) and a foreign-key guard; a database written by a newer app is refused.
- **Drivers.** One `ProviderDriver` interface per Provider (one account each): connection, `listModels`, `readUsage`, `startReply` → events, `stop`, `answerApproval`, `forkSession`, `rebuildSession`, `rewindSession`, `runOneShot` (titles, Summaries), `mcpSignIn`, and `capabilities` flags (`pdfAttachments`, `skillScriptsInPlainTrees`, `mcpOAuth`, `sseMcp`, `sessionFromTranscript`, …). **The UI branches on capabilities, never on the Provider's name.** Warm sessions close after 10 minutes idle (at most 6 idle Claude sessions stay open; one writing a Reply never closes, so more can be open while all are busy); Claude sessions run in streaming-input mode. Each driver runs in its own utility process, started when its Provider is connected, restarted on crash with backoff (1 s, 5 s, 30 s, then "Download <Provider> again", [§18](./18-offline-reconnect-and-error-states.md)), the in-flight Reply saved as failed with its displayed text.
- **Events** on one channel, every Reply event carrying `treeId`, `replyId` and an optional `subagentId`, with AG-UI names: `RUN_STARTED`, `TEXT_DELTA`, `TEXT_REPLACE`, `REASONING_DELTA` (display only), `TOOL_CALL_START/ARGS/END`, `TOOL_RESULT`, `APPROVAL_REQUESTED/RESOLVED`, `SUBAGENT_STARTED/FINISHED`, `FILES_CHANGED`, `TOKENS`, `CONTEXT_COMPACTED`, `RUN_FINISHED` (status and failure). Provider events: `PROVIDER_STATUS`, `USAGE_UPDATED`, `MCP_SERVER_STATUS`, `MODELS_CHANGED`, `SIGN_IN_STEP/FINISHED`. The list grows with new event types rather than overloaded ones. The contract is Zod schemas and its own source of truth; main maps rows to it.
- **MCP, Skills, Plugins.** Passed per session (Claude `mcpServers` with `strictMcpConfig`; Codex per-thread `config.mcp_servers`, stdio and HTTP only). MCP sign-in without a terminal on both (Claude's `mcpAuthenticate`, guarded by the weekly CI smoke; Codex `mcpServer/oauth/login` with file credential storage); the vendor programs own the tokens; servers are passed under stable ids. Skills from any folder (Claude `plugins` / config-folder skills; Codex `skills/extraRoots/set`); in plain ChatGPT Trees, user-picked Skills go in as `{type:"skill"}` and AI-picked ones through an app-owned `read_skill` MCP tool. Plugins are unpacked into their Skills and MCP servers; hooks never run. The login-shell environment is read once per launch for `PATH` and `${VAR}` values.
- **Security** ([ADR 0014](../../adr/0014-electron-security-posture.md)). Hostile: Reply content, previewed files, Archives/Themes/Skills/Plugins, the network; other same-user programs are out of scope. One window type with every `webPreferences` value explicit, never navigates, denies new windows and webviews; links open externally for `http`, `https` and `mailto` only; nothing from a Reply makes a request without a click (remote images are click-to-load chips through main); CSP as a header with no http sources and a session-level backstop; `app://` serves only the verified bundle and `uzfile://` serves files by id with `sandbox` and `nosniff`; HTML previews in an `allow-scripts`-only iframe; pdf.js, Mermaid strict, KaTeX untrusted; fuses off for RunAsNode, `NODE_OPTIONS` and inspect; no DevTools in production; vendor environment stripped of `ANTHROPIC_*`, `CLAUDE_*`, `OPENAI_*`, `CODEX_*` for correctness; every app `git` call ignores system and global config with hooks off; `userData` is owner-only; no secret ever in a command-line argument.

## Verify while building

- That `thread/revert` leaves the earlier part of a rollout intact for forks pointing into it; else fork at the leaf ([ADR 0004](../../adr/0004-app-keeps-provider-session-data.md)).
- Whether a crashed Turn's partial output is in the vendor's session at all before Retry rewinds ([#38](https://github.com/qodesmith/unimatrix-zero/issues/38)).
- That no Provider host launches our binary as Node; Claude's 2 s graceful refresh wait when the utility process dies ([#39](https://github.com/qodesmith/unimatrix-zero/issues/39), [#40](https://github.com/qodesmith/unimatrix-zero/issues/40)).
- Claude's `mcp-needs-auth-cache.json` is cleared after an MCP sign-in ([#38](https://github.com/qodesmith/unimatrix-zero/issues/38)).
