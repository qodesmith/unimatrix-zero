# 5. Canvas mode and chat mode

Source: [Canvas mode UX](https://github.com/qodesmith/unimatrix-zero/issues/14) (prototype, variant D), [Chat mode Thread navigation and switching between modes](https://github.com/qodesmith/unimatrix-zero/issues/15) (answered by #14), [Canvas engine](https://github.com/qodesmith/unimatrix-zero/issues/19), [ADR 0019](../../adr/0019-canvas-is-a-display-for-the-tree.md).

- **Canvas mode is the app.** One canvas holds exactly one Tree, rendered with React Flow. Two orientations share every feature: **vertical** (top-down, the default; Prompt and Reply as separate equal-width boxes) and **horizontal** (left-to-right; one card per **Exchange**, Prompt as header, Reply as body). The toggle animates Turns to their new positions. Orientation is a global Setting; the canvas toggle is a shortcut to it.
- **Chat mode is a slideout** on the right that opens on a Reply's Thread from the chevron at the top right of that Reply, can expand to full screen, and has exactly one Input at the end of the shown Thread. A click on a Turn's box opens nothing. To switch Threads, open it from another Reply on the canvas; there is no Thread switcher. Sending from the slideout into a Reply that already has a response branches, and the slideout follows the new Branch.
- **Layout and navigation.** Layout comes from the Tree: Turns cannot be dragged, Branches read oldest-first. Scroll pans, pinch or ⌘-scroll zooms. On submit the canvas pans to center the new Reply, keeps the zoom and does not follow it as it grows. A single-Thread Tree keeps its zoom; the first Branch zooms out just enough to show the whole Tree.
- **Thread highlighting.** The Active Thread's path to the root is highlighted; hovering a Turn redraws the highlight on that path only while the pointer is there, then it returns to the Active Thread. With the slideout open, its Thread is the default highlight. Focusing any Reply's Input makes the Thread ending at that Reply the Active Thread (the sidebar's files follow, any selection clears, the slideout closes, the canvas does not pan).
- **Collapse a Branch.** A Fork folds and unfolds its Branches through its Fork pill ("Fork · N Branches"); the toggled Reply stays put on screen.
- **Grouped controls** at bottom-left: a minimap (hidden by default, shown from a toggle), zoom, orientation toggle, and an attention indicator ("N streaming" / "N failed", click to jump to each).
- **Capped height.** Long Prompts and Replies scroll inside a capped height with Show more / Show less (a Setting, on by default). A streaming Reply stays on the newest text unless the user scrolls up. Each Reply shows its Context size badge, with an info button that slides a details drawer over the blurred Reply (what this Exchange added, the Thread up to here, the Context window), and an optional Context size meter (a thin bar toward the Model's limit; a Setting, on by default).
- **Delete** from a Prompt uses a hover overlay with an inline confirmation showing the Turn count and "Deleting frees up to X"; nothing shifts. There is no Undo: "This can't be undone." Deleting rewinds the Provider session so the AI never sees deleted Turns ([ADR 0004](../../adr/0004-app-keeps-provider-session-data.md), amended).
