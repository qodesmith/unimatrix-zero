# 8. System prompts, the Tools panel, approvals and YOLO

Source: [Capability tiers and system prompts](https://github.com/qodesmith/unimatrix-zero/issues/9), [Workspaces](https://github.com/qodesmith/unimatrix-zero/issues/24), [Subagents in every Tree](https://github.com/qodesmith/unimatrix-zero/issues/32), [Provider drivers, process model and IPC event list](https://github.com/qodesmith/unimatrix-zero/issues/38), [Electron security posture](https://github.com/qodesmith/unimatrix-zero/issues/39) Q18.

- **Trees are plain by default.** Plain means no files, not no tools: web search, MCP servers, Skills and Subagents still run. A Workspace is an optional property of the Tree ([§9](./09-workspaces.md)).
- **System prompt.** Set per Tree as a copy of the global default; changeable at any time, applying to later Replies with the re-read note. Each Reply records the exact text it ran under (an internal, read-only history). Presets ship read-only: **Default** (a plain helpful assistant, good with Markdown, no mention of agents), **Concise**, **Explain simply**, **Coding helper**; Duplicate makes an editable copy. The library in Settings holds presets, the user's own, and the global default; "Save to library…" on a Tree's panel turns a variant into an entry. Deleting the current default falls back to the Default preset. Both Providers accept a full replacement under subscription sign-in; Claude prefixes one identity sentence of its own and needs `snapshot: false`. Workspace Trees add an app-written **Workspace section** under the System prompt ([§9](./09-workspaces.md)); with run commands on, the vendors' own agent prompts are used with the System prompt appended.
- **What is never loaded** from the user's own setup: user-level `CLAUDE.md` / `AGENTS.md` and user settings (hooks, permissions, model, output style). What can be: the user's MCP servers, Skills and Plugins through the app's own libraries ([§17](./17-settings-and-themes.md)), and a linked folder's own `CLAUDE.md` / `AGENTS.md` (the search up through parent folders is to be blocked, a [§9](./09-workspaces.md) verify item; `.codex/config.toml` is never loaded). Plugin hooks never run.
- **Plain ChatGPT Trees** are locked down in layers because Codex has no clean "no tools" mode: `environments: []`, feature flags off, `approvalPolicy: untrusted` with every request auto-declined, a deny-all `PreToolUse` hook if per-thread hooks load, an empty app-owned `cwd`, and any tool call that still gets through is shown in the Reply. `features.multi_agent` is not part of this; Subagents are controlled by `agents.enabled` ([§11](./11-subagents.md)).
- **The Tools panel** (per Tree, defaults in Settings → Tools): web search (always on by default), Subagents (on), each MCP server, Skill and Plugin from the libraries (on, except where noted), Claude account connectors (**off** by default: about 30k tokens per cold Turn), the vendors' built-in Skills and Codex's remote plugins (off, listed in a "Built in" group per Provider), and the Workspace permission level. Skills that run scripts are marked "needs a Workspace with commands" on ChatGPT. Toggles apply live with no visible resume dance.
- **The approval card** is inline in the Reply where the tool call happened; the stream pauses there. Allow once / Always allow in this Tree / Deny, with "This happens outside this Thread, so other Branches will see it too." It names the Subagent asking, if any. Once answered it collapses into a chip (✓ allowed / ✕ denied); in canvas mode a waiting Turn gets a badge. The app enforces this on both Providers (Claude `canUseTool` plus `PreToolUse`; Codex per-server `approval_mode` and approval requests). Read-only tools run without asking where the marker exists. Writes inside the working copy are auto-approved; commands inside the Sandbox run without a card ([§10](./10-the-sandbox.md)).
- **Reviewing additions.** A review screen appears only when an addition includes an MCP server with a local command: one screen per add action, listing `command` and `args`, Skill names, and what was dropped. Changed local-server definitions in a Plugin stay off with a "1 change to review" badge until accepted.
- **YOLO.** One global Setting, off by default, confirmed once when turned on, with a badge beside the Input. It removes approvals and the Sandbox together (Claude `bypassPermissions` with the Sandbox off; Codex `danger-full-access` with `approval_policy: never`). It never widens what a Tree can do: tools that are off stay off, write-only stays write-only, plain stays plain. No per-Tree YOLO; "Always allow in this Tree" covers that.
