# 6. The Input: Prompts, attachments, Models

Source: [Canvas mode UX](https://github.com/qodesmith/unimatrix-zero/issues/14), [Switching model and provider within a Tree](https://github.com/qodesmith/unimatrix-zero/issues/10), [Capability tiers and system prompts](https://github.com/qodesmith/unimatrix-zero/issues/9), [Settings and user preferences](https://github.com/qodesmith/unimatrix-zero/issues/22).

- **Where the Input is.** The Active Thread always shows its Input; every other Reply reveals one on hover, and a hover Input holding a draft stays until sent or cleared. An empty Tree shows one centered Input that creates the root Prompt. Submitting into a Reply that already has a response branches.
- **Send key** is a Setting: "Enter sends · Shift+Enter adds a new line" (default) or "Enter adds a new line · ⌘/Ctrl+Enter sends".
- **Model picker.** Every Input has one, defaulting to the Model of the Reply it is attached to; a new Tree starts from the last-used Model. Models are listed at runtime from each Provider. Models the current vendor program is too old for show disabled as "Needs an app update" (or "Update available"). A retired Model falls back to the Provider's current default, visibly. A signed-out Provider's Model offers "Sign in again" beside the picker ([§18](./18-offline-reconnect-and-error-states.md)); a removed Provider's Model falls back visibly too, until the Provider is connected again ([#22](https://github.com/qodesmith/unimatrix-zero/issues/22)). The Thread is never blocked and the Model never changes without the user seeing it.
- **Switching Model or Provider** continues in the same Tree. Within a Provider, the session is kept. To another Provider, the Thread is handed over through one "rebuild session from Thread" path: ChatGPT takes real history through `thread/inject_items`; Claude takes a text replay in one user message. The full Thread is always sent, never cut or summarized. Replies written by another Model get a hidden `[Reply written by <Model>]` label and one app-written line in the System prompt explains it; the user never sees the labels. Thinking never carries over; tool calls and citations become plain text. Every Reply shows a Provider icon and a Model pill.
- **The re-read note.** One inline note above the Input (never a modal), shown only above about 20k tokens, for anything that re-reads the Thread cold: switching Provider, a System prompt change, an expired prompt cache, forking into a new working copy, turning on run commands. Wording talks about the user's limit ("Switching to ChatGPT will re-read ~48k tokens of this conversation (uses more of your limit)."). The estimate is Context size plus setup overhead. A Setting hides the note.
- **Attachments.** An attach button plus paste and drop. Images show as thumbnails with a lightbox; other files as chips (name, size). The Tree keeps every original file (under `userData/attachments/`, named by SHA-256) and converts fresh from it on every hand-over, so losses never pile up. Text-like files go inline as text to both Providers. Claude takes images, PDFs and text inline. Codex takes images only (its `app-server` protocol has no PDF or document input, checked against the current source), so every PDF that reaches ChatGPT, whether attached to a ChatGPT Prompt or handed over with the Thread, goes through pdf.js page by page: a text page as text, a page with no text or with images over about 10% of it as an image plus its text. The note says so ("1 PDF sent as text (layout and images not included)"), conversions are cached, and the attach option is never disabled. In a Workspace Tree the original PDF is also copied into the working copy so the model can read it with its file tools. This is the reconciled reading of [Capability tiers and system prompts](https://github.com/qodesmith/unimatrix-zero/issues/9), which disabled the option in plain Trees before the conversion existed, and [Switching model and provider within a Tree](https://github.com/qodesmith/unimatrix-zero/issues/10), which added it.

## Verify while building

- How the ChatGPT desktop app handles a PDF the user attaches in Codex mode (the app-server protocol has no PDF input, so it most likely places the file in the working copy for the Model's file tools); confirm the copy the app writes into the working copy lands where Codex's file tools look.
- Claude's exact limit weighting for cached tokens, which the re-read note's wording assumes ([#7](https://github.com/qodesmith/unimatrix-zero/issues/7)).
