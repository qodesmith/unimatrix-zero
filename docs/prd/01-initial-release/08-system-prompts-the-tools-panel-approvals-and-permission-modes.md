# 8. System prompts, the Tools panel, approvals and Permission modes

Source: [Capability tiers and system prompts](https://github.com/qodesmith/unimatrix-zero/issues/9), [Workspaces](https://github.com/qodesmith/unimatrix-zero/issues/24), [Subagents in every Tree](https://github.com/qodesmith/unimatrix-zero/issues/32), [Provider drivers, process model and IPC event list](https://github.com/qodesmith/unimatrix-zero/issues/38), [Electron security posture](https://github.com/qodesmith/unimatrix-zero/issues/39) Q18, [ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md), which supersedes #9's plain Trees, tiers and YOLO.

- **One kind of Tree.** Every Tree can read files anywhere on disk, write files and run commands, as far as the Permission mode allows, and web search, MCP servers, Skills and Subagents run as its Tools panel says. Every Tree has its own files ([§9](./09-the-trees-files.md)); there are no plain Trees and no Workspace to turn on, and the user never sees the word Workspace.
- **System prompt.** Set per Tree as a copy of the global default; changeable at any time, applying to later Replies with the re-read note. Each Reply records the exact text it ran under (an internal, read-only history). Presets ship read-only: **Default** (a plain helpful assistant, good with Markdown, no mention of agents), **Concise**, **Explain simply**, **Coding helper**; Duplicate makes an editable copy. The library in Settings holds presets, the user's own, and the global default; "Save to library…" on a Tree's panel turns a variant into an entry. Deleting the current default falls back to the Default preset. Every Tree runs the vendors' own agent prompts (Claude's `claude_code` preset, Codex's base instructions) with the System prompt added after them, as T3 Code does ([ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md)); Claude needs `snapshot: false` for a change to apply. Every Tree adds an app-written **files section** under the System prompt ([§9](./09-the-trees-files.md)).
- **What is never loaded** from the user's own setup: user-level `CLAUDE.md` / `AGENTS.md` and user settings (hooks, permissions, model, output style). What can be: the user's MCP servers, Skills and Plugins through the app's own libraries ([§17](./17-settings-and-themes.md)), and a linked folder's own `CLAUDE.md` / `AGENTS.md`. Claude runs with `settingSources: []` ([§20](./20-distribution-updates-and-vendor-programs.md)), which loads no `CLAUDE.md` at all, so the app reads the file at the linked folder's root itself and passes it to the session; parent folders are never read. Codex reads `AGENTS.md` on its own, so stopping its walk up through parent folders is a [§9](./09-the-trees-files.md) verify item. `.codex/config.toml` is never loaded. Plugin hooks never run.
- **The Tools panel** (per Tree, defaults in Settings → Tools): web search (always on by default), Subagents (on), each MCP server, Skill and Plugin from the libraries (on, except where noted), Claude account connectors (**off** by default: about 30k tokens per cold Turn), and the vendors' built-in Skills and Codex's remote plugins (off, listed in a "Built in" group per Provider). Tools switched off stay off in every Permission mode. Toggles apply live with no visible resume dance.
- **The approval card** is inline in the Reply where the tool call happened; the stream pauses there. Allow once / Always allow in this Tree / Deny, and for anything outside the Tree's files, "This happens outside the conversation, so other Branches will see it too." It names the Subagent asking, if any. Once answered it collapses into a chip (✓ allowed / ✕ denied); in canvas mode a waiting Turn gets a badge. The app enforces this on both Providers (Claude `canUseTool` plus `PreToolUse`; Codex per-server `approval_mode` and approval requests). Which actions reach a card is the Permission mode's call (below); reads never do, and read-only MCP tools run without asking where the marker exists.
- **Reviewing additions.** A review screen appears only when an addition includes an MCP server with a local command: one screen per add action, listing `command` and `args`, Skill names, and what was dropped. Changed local-server definitions in a Plugin stay off with a "1 change to review" badge until accepted.
- **Permission modes.** One global Setting ([§17](./17-settings-and-themes.md)), modeled on T3 Code's, that replaces YOLO ([ADR 0022](../../adr/0022-one-kind-of-tree-and-permission-modes.md)). Reads never ask in any mode, because Codex cannot restrict them and a read card would be a promise only Claude keeps.
  - **Full access** (the default): no approval cards and no Sandbox. Claude `permissionMode: 'bypassPermissions'` with `allowDangerouslySkipPermissions`; Codex `danger-full-access` with `approval_policy: never`. Nothing is protected, credentials included; the maintainer accepts that risk.
  - **Auto:** the vendor's own reviewer decides. Claude `permissionMode: 'auto'`; Codex `on-request` with its `auto_review` reviewer.
  - **Auto-accept edits:** edits inside the Tree's files go ahead, and edits elsewhere get a card. Commands run inside the Sandbox without asking; leaving it gets a card ([§10](./10-the-sandbox.md)).
  - **Supervised:** every edit and every command gets a card. Commands run inside the Sandbox.
  - "Always allow in this Tree" still covers trust in one Tree. Whether a Tree or a Prompt can also pick its own mode, as in T3 Code, is open (below).

## Verify while building

- What the vendors' agent prompts cost a cold first Turn on Claude, which re-read about 36k tokens of Claude Code's prompt and tool definitions in [#7](https://github.com/qodesmith/unimatrix-zero/issues/7), and how the re-read note counts it.
- Whether the Permission mode is only global or also per Tree or per Prompt, and when a change reaches a streaming Reply (ADR 0022, open).
- Claude's `permissionMode: 'auto'` under subscription sign-in with `settingSources: []` (Agent SDK 0.3.307), Codex's `auto_review` through `app-server`, whether the Sandbox holds in Auto, and what the user sees when either reviewer refuses (ADR 0022, open).
- The exact settings for Supervised: Claude `default` with the Sandbox's automatic approval of sandboxed commands off, and the Codex approval policy that gives every command a card (ADR 0022, open). Auto-accept edits keeps ADR 0018's: Claude `acceptEdits` with sandboxed commands approved automatically, Codex `on-request`.
