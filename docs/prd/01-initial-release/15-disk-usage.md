# 15. Disk usage

Source: [Disk usage and low disk space](https://github.com/qodesmith/unimatrix-zero/issues/29), [ADR 0010](../../adr/0010-linked-folder-holds-one-thread.md).

- **The app never deletes data on its own.** Stored data goes only when the user deletes what it belonged to, and cleanup after a deletion never blocks: unreferenced Provider session data, working copies whose leaf is gone, Snapshot refs of deleted Replies (occasional `git gc`), unreferenced attachments, provider-side sessions best-effort through official APIs only.
- **One figure per Tree, "Deleting frees up to X"**: only data the Tree alone owns (its Turns, Provider session data, attachments no other Tree uses, cached conversions, its hidden store at real compressed size, large-file versions, working copies at full size). Linked folders are never counted or touched. Deleting a Branch frees its unique data too, with the same figure.
- **Where:** Settings → Storage (the app's total, free space, every Tree by size with Delete / Reveal, and an off-by-default "Show breakdown" switch: Turns, Provider sessions, Attachments, Converted attachments, File history, Large files, Working copies), "Storage…" in the Tree menu, and the figure in delete confirmations. Nothing in the sidebar.
- **Low disk** (under 5 GB or 5%, whichever is smaller; the app's disk plus a linked folder's disk): a dismissible band "Your disk is almost full (X left). See what's using space →". **Critical** (under 1 GB): the band cannot be dismissed, and new working copies, "Put this Thread in the folder", Archives, restores and vendor program downloads are blocked; Replies keep running. If the disk fills mid-Reply the Reply fails like any other, keeping its partial text; a Snapshot that cannot be written marks the Reply "Files not saved for this Reply".
- **Fit checks** (size plus 1 GB) before Archive, restore, a new working copy, "Put this Thread in the folder" and vendor downloads, refused before anything is written, with one sentence and one action; Archives also offer saving to another drive.
