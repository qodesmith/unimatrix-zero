# 9. Workspaces

Source: [Workspaces](https://github.com/qodesmith/unimatrix-zero/issues/24), [Workspaces: snapshots, working copies and linked folders](https://github.com/qodesmith/unimatrix-zero/issues/25) (amended), [Workspace file tree and canvas](https://github.com/qodesmith/unimatrix-zero/issues/26) (prototype, variant A plus C's chips), [ADR 0010](../../adr/0010-linked-folder-holds-one-thread.md).

- **Two independent choices** per Workspace: where the files live (**app-owned**, the default, in `userData`; or a **linked folder** of the user's) and what the AI may do (**Write files**, the default; or **Write files + run commands**). App-owned → linked is a one-way "Move Workspace to a folder…", which accepts only a new or empty folder ([#27](https://github.com/qodesmith/unimatrix-zero/issues/27)). A plain Tree's empty files area says "Add files to this Tree" with the two options.
- **Every Reply has a Snapshot**: the files as they stood when it finished. A Reply that changed nothing reuses its parent's. Viewing any Turn shows its Snapshot without touching disk. User edits between Replies are caught by a snapshot at the start of each Turn (about 150 ms on 23k files) and recorded as a **User edit** ("Edited by you"); the AI is told. A watcher (`@parcel/watcher` or recursive `fs.watch`, not chokidar) only keeps the UI live.
- **Storage.** One hidden git store per Workspace in `userData`, one index per working copy, never the user's `.git`, no `git worktree`, nothing the user can see. Ignore rules: every nested `.gitignore` and `.git/info/exclude`, read by the app, plus default excludes (`node_modules`, `.venv`, build folders). Every version of every file is kept; files of 100 MB or more live in a per-Workspace folder named by hash with a pointer in the Snapshot, placed in working folders as copy-on-write clones or full copies, never links. The app never deletes data on its own ([§15](./15-disk-usage.md)).
- **Working copies.** One per Thread that is not in the folder, created on the first Prompt sent into it (viewing never creates one), reused as the Thread continues, deleted when its leaf is deleted or its Thread moves into the folder, never evicted. Ignored files reach a new working copy by a copy-on-write clone where the filesystem allows, otherwise a capped copy of small ignored files, plus an optional per-Workspace **Setup command** (run commands only; the user's own command, outside the Sandbox). The Workspace section tells the AI what is missing. Forking into a new working copy is a cold Turn on both Providers (the re-read note).
- **Linked folders.** The real folder holds exactly one Thread. Linking snapshots it as it is, uncommitted edits included; the user's staging area, branch and `git status` are never touched. Non-git folders are allowed with default excludes and a size cap; folders still too large after excludes (around 50k files) are refused with a plain explanation. The folder changes Thread only through **"Put this Thread in the folder"** (snapshot first, replace, never merge), or the per-Workspace setting **"Keep the folder in sync with the selected Thread"** (off by default; waits for a generating Reply, with a note). Hand edits caught by a swap become a User edit on the outgoing Thread.
- **Permissions.** Writes inside the working copy are auto-approved on both kinds (Claude's five file tools with `acceptEdits`; Codex `workspace-write` with `shell_tool` off and temp excluded); writes outside go to the card. Other Branches' files and the hidden store are a hard deny without asking. Overwriting User edits is prevented by both Providers refusing edits to files changed since last read, and by Snapshots. Commands each go to the card unless the Sandbox covers them ([§10](./10-the-sandbox.md)). Turning on run commands mid-Tree applies to the whole Tree from then on, with the re-read note.
- **The Workspace section** of the prompt is app-written, never a Setting, under about 400 tokens: the working folder and that it is the only place to write, the permission level, how to read another Branch's files when asked to combine them (read-only paths), the User edits since the last Reply. The prompt explains; code enforces.
- **File tree and canvas.** One sidebar: Trees above, a view-only file tree ([@pierre/trees](https://trees.software/)) below that follows the Turn selected on the canvas (else the active Thread's leaf), colored by what that Reply added, changed or deleted. No folders mirroring the Tree, no Segments. A Reply lists the files it changed and the commands it ran as **chips** under its text; clicking a chip opens the file as it was at that Reply. The Files header says only where the files live (a linked folder's path, cut at 60% with a tooltip; no badge for app-owned).
- **Opening files.** At a Thread's leaf (the only version on disk): Open in default app and Reveal in Finder. At earlier Turns: Open this version and **Save a copy…** (a one-time copy of that Reply's files to a chosen folder). Open is refused for files with the executable bit; HTML defaults to the in-app preview with Open in browser as the explicit choice; Open in editor uses an editor main detected, offered for linked folders first.
- **Previews**, in three tiers: in the app (images, audio, video, PDF via pdf.js, Markdown through the same hardened pipeline as Replies, CSV as a table, code and text detected from bytes), the OS (Quick Look on macOS for Office and the like, OS thumbnails and icons), and a fallback card. Long text previews its start; very large files are not previewed; files stream through `uzfile://` with range requests. The security rules for each type are in [ADR 0014](../../adr/0014-electron-security-posture.md).

## Verify while building

- Stopping Codex's `AGENTS.md` walk up through a linked folder's parents, and confirming that Claude under `settingSources: []` reads no `CLAUDE.md` from the folder or its parents, so the one the app passes in is the only one ([#24](https://github.com/qodesmith/unimatrix-zero/issues/24)).
- Copy-on-write clones on Linux and Windows filesystems; Windows and Linux snapshot and watcher performance; Linux inotify watch limits ([#25](https://github.com/qodesmith/unimatrix-zero/issues/25)).
- Electron's bundled codecs (H.264, AAC), whether its PDF viewer is on by default (it is turned off), and calling `previewFile()` from the renderer ([#26](https://github.com/qodesmith/unimatrix-zero/issues/26)).
- Whether Windows `createThumbnailFromPath` loads shell thumbnail handlers in-process; if so, use only our own thumbnails and icons ([#39](https://github.com/qodesmith/unimatrix-zero/issues/39)).
- Whether app-owned Workspaces need a temporary copy for Open at earlier versions, and whether Open in editor is offered for them ([#26](https://github.com/qodesmith/unimatrix-zero/issues/26), [#39](https://github.com/qodesmith/unimatrix-zero/issues/39)).
