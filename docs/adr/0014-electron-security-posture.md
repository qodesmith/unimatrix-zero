# Electron security posture: the window only ever shows the app

We treat four sources as hostile: Reply content (anything that came through web search, MCP tool output or a Workspace file can carry a prompt injection), files previewed from a Workspace or linked folder, things a user is sent and adds (Archives, Themes, Skills, Plugins), and the network (bundle, manifest and vendor program downloads). Other programs running as the same OS user are out of scope: they can already rewrite `userData`, the database and the vendor programs, so anything we did would only look like protection. Against the four, the app's window only ever shows the app: it never navigates anywhere, nothing from a Reply makes a network request without a click, and the renderer reaches main only through one three-member bridge that sends ids, never paths. Findings: [Electron security posture](https://github.com/qodesmith/unimatrix-zero/issues/39).

## Consequences

- **One window type.** A single `createWindow` helper sets every `webPreferences` value explicitly (`contextIsolation`, `sandbox`, no `nodeIntegration`, `webSecurity`, no `webviewTag`, `plugins: false`, `devTools: false` in packaged builds). Navigation and new windows outside our scheme are cancelled and handed to the link rule; `will-attach-webview` is always blocked. Dev serves Vite through `app-dev://`, proxied from main, so the window's origin rules are the same in dev and packaged builds. The one allowance is Vite's HMR websocket, which the page must open itself: a dev run adds `ws://localhost:<vite port>` to `connect-src` and the session backstop, and nothing else ever gets a localhost exception. Amended: this allowance was decided in [#62](https://github.com/qodesmith/unimatrix-zero/issues/62). A future in-app browser would be a main-owned `WebContentsView` with its own session, never the app window navigating.
- **The bridge is `window.uz = { send, subscribe, registerDroppedFile }`** and never grows per feature. Main parses every command with `z.strictObject` before any handler and rejects any sender that isn't our top-level frame. The renderer refers to files by ids; main resolves them and checks containment by realpath, because the AI can make symlinks. Real paths enter only through native dialogs and dropped files, whose paths the preload hands to main without the page seeing them.
- **Links open in the default browser, and only `http:`, `https:` and `mailto:`.** Every other scheme is a set of handlers we can't review (`ms-msdt:` was one-click code execution). Opening files is an app action, not a link: Open (document types only, never a file with the executable bit), Reveal in Finder, Open in editor. Amended: "Show in Finder" is now Reveal in Finder, the name [#26](https://github.com/qodesmith/unimatrix-zero/issues/26) settled on.
- **No zero-click network.** Remote images are click-to-load chips fetched through main; link icons are built in. The renderer's CSP is sent as a header with no `http:`/`https:` sources, and the window's session cancels any http or ws request as a backstop.
- **Two schemes.** `app://` serves only the verified app bundle ([ADR 0007](0007-thin-shell-signed-app-bundles.md)): one `.asar` checked against the signed manifest at launch, a manifest `sequence` that never goes backwards, and downloads checked by hash before they're moved into place. `uzfile://` serves Workspace files and attachments by id with `Content-Security-Policy: sandbox` and `nosniff` on every response; HTML previews render in an `allow-scripts`-only iframe with no network, SVG only as `<img>`, PDFs through pdf.js.
- **No DevTools in production.** Whoever has the console has everything the UI can do; bug reports use a diagnostics export instead. Turning it back on is a bundle update, not a shell release. Amended: Reports are assembled and sent by main, on a click, through a stateless relay ([ADR 0017](0017-reports-go-through-a-stateless-relay-into-github-issues.md)).
- **Fuses and permissions.** RunAsNode, `NODE_OPTIONS` and `--inspect` are off and asar integrity is on, so nothing can run code as our app and inherit its macOS privacy grants. Permission requests are denied by default; the one grant is `clipboard-sanitized-write`, so Copy works. Amended: decided in [#62](https://github.com/qodesmith/unimatrix-zero/issues/62).
- **Untrusted files are parsed, not trusted.** Archives are checked against strict schemas and restore only git objects and our own refs into a fresh store; every `git` call the app makes ignores system and global config and disables hooks and fsmonitor. Themes keep only known fields. Adding a local-command MCP server shows its command once for review.
- **Vendor environment is about correctness, not secrets.** `ANTHROPIC_*`, `CLAUDE_*`, `OPENAI_*` and `CODEX_*` are stripped so the connected subscription is the one that answers and bills; an AI that can run commands can still read the user's files, which is the vendor sandboxes' job ([ADR 0018](0018-commands-run-inside-the-vendor-sandbox.md)).
- **Shell releases for Chromium fixes are noticed by CI**, which opens an issue for high or critical Electron advisories on our major.
