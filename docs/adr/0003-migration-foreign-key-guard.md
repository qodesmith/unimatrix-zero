# Migrations run behind a backup and a foreign-key guard

Before applying pending migrations the app copies the database file (keeping the last three), sets `PRAGMA foreign_keys=OFF`, runs Drizzle's `migrate()`, runs `PRAGMA foreign_key_check`, and turns foreign keys back on; if the check fails it restores the copy and shows an error. This works around [drizzle-orm#5782](https://github.com/drizzle-team/drizzle-orm/issues/5782): a migration that rebuilds a parent table silently deletes child rows under `ON DELETE CASCADE`, which was reproduced with our Tree/Turn schema and would wipe users' conversations. Do not remove the guard unless that bug is fixed in the Drizzle version in use. The app also refuses to open a database written by a newer app version, since Mac users update manually and may run an older build.
